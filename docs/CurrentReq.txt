NFR (Horizon 0 slice)
NFR-01 (publish within 60 min, alert on failure) — Built. A 5pm ET checkpoint job checks whether today's publication was recorded; if not, emails the admin via a shared SMTP helper (services/email_service.py). Also callable on demand (admin "Send Test Alert" button, or POST /api/v1/signals/check-publication-alert).
NFR-02 (auto-recover, missed day alerted within 2h) — Built. Same mechanism as NFR-01, second checkpoint at 6pm ET (2h after the 4:10pm publish job) so a missed/failed run gets flagged same-day, not silently carried into the next day.
NFR-03 (quarterly restore-tested backups) — Built. Nightly pg_dump of the published-record + PIT-store tables (published_signals, signal_outcomes, pit_prices, pit_universe_membership, pit_fundamentals, backtest_runs) to S3 (public access blocked, 30-day lifecycle), with a free structural check every run and a genuine restore-into-a-throwaway-database test (exact row-count comparison, not just "the file parses") quarterly and on demand. Admin UI on the Scheduler page shows the last 10 runs. Caveat: the S3 credentials are the existing broad-permission deploy key, not a scoped IAM role — a scoped role was attempted first and blocked by the AWS account's own permissions (no iam:CreateRole on the stored credentials), so this is a documented tradeoff, not an oversight.
