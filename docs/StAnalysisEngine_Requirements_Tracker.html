Requirements Review

Stock Analysis Features Requirements (v0.1 draft, Sep 27, 2026) · Recommended improvements · October 1, 2026

The biggest problem isn't the wording. The track record doesn't measure the scores users actually see, and a few "Have" items quietly break the document's own principles. Fix those first, then clean up the document's structure.

1. Fix the trust gaps

The track record tests a different model than the stock pages show. TRK-2 says published_signals is "a pure momentum rank" with no signal type. But the Buy/Hold/Trim scores from SCR-1 and SCR-2, which drive the stock page, aren't what's being recorded. For a Phase 1 whose whole theme is trust, that's the core gap.

  • Add a requirement that every nightly SCR-1/SCR-2 score is published append-only into the track record, with signal, confidence, horizon, factor values and model version.
  • Until then, label the current record as tracking a momentum ranking, not the stock-page signals.

Point-in-time data isn't really met. Earnings surprise, revisions and quality come from yfinance's current snapshots ("source: live", no PIT table). That conflicts with the "No look-ahead" principle, NFR-1 and scenario S3.

  • Either require a PIT store that snapshots fundamentals daily from now on, or mark those factors as excluded from backtests.
  • Add a status column to the NFRs. Right now nothing confirms the PIT test in S3 actually exists.

"Confidence" has no definition. SCR-2 uses score plus label, TRK-3 uses a stability proxy, and S1 says "68% confidence" as if it were a probability. Calibration only makes sense if confidence means "estimated probability of a hit."

  • Define it once, in one place, and use it everywhere.
  • Today both populated buckets show 70%, so calibration isn't telling users anything yet.

Weights have never been validated. SCR-1 weights are "reasoned defaults, not backtested," and REG-1 shipped after failing its own validation gate three times.

  • Add a model validation requirement: a minimum out-of-sample IC or hit rate on a hypothetical backtest before a model version can publish.
  • Add a documented override process (who approves, what disclosure appears) so the REG-1 exception follows a rule instead of being ad hoc.

A live AI feature is missing its Must guardrails. ASK-1 is live, but ASK-2 ("I don't know") is Missing and ASK-1 cites no sources, which also breaks NFR-5. Either gate ASK-1 behind ASK-2 and citations, or make that an explicit release blocker.

Data licensing is a blocker, not an open question. yfinance is an unofficial Yahoo scraper, and its terms generally don't allow commercial display. If this goes public, open question #1 has to be answered before launch. Each requirement should name its actual source, because section 6 still says "data vendor" while the code uses yfinance.

2. Separate the spec from the status log

The Gap column has become an engineering changelog: bug fixes, "live-verified," and quoted values like $10,579.60. That's useful, but it buries the requirement.

  • Requirements doc: ID, priority, requirement, acceptance criteria. Change these only on purpose, through version bumps.
  • Status tracker (a separate sheet or tab): ID, status, evidence (a test, endpoint or screenshot), limitation, date.
  • Add a status: "Built, data maturing" for items like EXP-4 (only about 2 days of history so far). That's different from a feature gap.
  • Bump the version. It's still "0.1 draft, Sep 27," yet Phases 1 and 2 have shipped. The audit note also says "after Phase 1 shipped," while every Phase 2 item is marked Have.

4. Add what's missing

  • Success metrics for the purpose statement, such as weekly active users, track-record page views, alert open rate, and 12-month model IC.
  • Operations: what users see when the nightly job fails or data is stale, job-failure alerting, and data-quality checks (missing factors, outliers).
  • Model governance: what triggers a new model version, who approves it, and the record start date (open question #3).
  • Security and privacy for portfolio data, the webhook secret, and account deletion.
  • Compliance as testable requirements. Turn section 8 into IDs (CMP-1…) with acceptance criteria, for example "every returns chart shows the past-performance disclaimer."
  • Evidence for performance claims. DET-1 and SCN-1 are marked Have with no p95 measurement attached.
  • Chart depth on DET-1, for parity with tools like TradingView: compare-to-SPY overlay, a few indicators (moving averages, RSI), and log scale.

5. Re-prioritize Phase 3

STR-1 (Should) is a prerequisite for STR-3 (Must). Either raise STR-1 or make STR-3 "Must if STR ships." Also consider moving PPR-1's SPY comparison earlier, since it's small and reuses the TRK-6 logic.

Automated Trading Agent Requirements

Oct 1, 2026 · Amit · Phase 4 of the Stock Analysis app · Version 0.1 draft

Purpose and principles

The agent runs the app's signals as a disciplined, rule-based portfolio on Alpaca. Its first goal is to limit losses; its second is to beat SPY on a risk-adjusted basis. No agent can guarantee profits, so these requirements focus on what it can control: position sizes, exposure, stops, costs and an audit trail.

  • Risk rules are code, not suggestions. A deterministic risk layer approves every order. Neither the strategy nor the AI can override it.
  • AI can only make the plan safer. The AI reviewer may remove or shrink buys. It can never add trades, enlarge them, or block risk-reducing sells.
  • Paper first. Live trading requires passing the validation gate and is off by default.
  • Every action is explained and logged. Each order records why it was placed, in plain words.

Priority: Must for this phase's release, Should soon after.

Modes and safety

The agent places no orders until a person deliberately turns it on, and one control stops it at any time.

IDPriorityRequirementAcceptance criteria
AGT-1MustThree modes: Plan (compute and show orders, place none), Paper (Alpaca paper account), Live (real money). Default is Plan.A new install places no orders until the mode is changed.
AGT-2MustLive mode requires (a) the AGT-30 validation gate passed, (b) explicit user opt-in with typed confirmation, and (c) a server-side ALLOW_LIVE_TRADING flag.Live orders are rejected if any of the three is missing; the rejection is logged.
AGT-3MustKill switch: one control in the UI (and an admin flag) stops all new orders immediately, leaving existing protective stops in place.After activation, no new order is submitted on the next run; stops remain open.
AGT-4MustRuns on a schedule (default once daily at 15:45 ET on trading days), only when the broker clock says the market is open.No orders on market holidays or outside session hours.

Strategy and signals

Buys come only from the app's own Buy signals that also pass trend, liquidity and earnings filters; exits follow stated rules.

IDPriorityRequirementAcceptance criteria
AGT-5MustCandidates come from the app's SCR-1 scores (short-term, 10–90 day holds), restricted to Buy signals.Every buy traces to a stored score and signal for that date.
AGT-6MustTrend filter: only buy stocks above their 200-day moving average.No buy for a stock below its 200-DMA on that date.
AGT-7MustLiquidity filter: only trade stocks with 20-day average dollar volume of $50M or more.Illiquid names never appear in orders.
AGT-8MustEarnings blackout: no new buys within 2 trading days before a company's earnings (reuses ERN-1 data).Candidates with earnings in the window are skipped, with the reason logged.
AGT-9MustExit when a holding's signal drops to Trim, it closes below its 200-DMA, or it leaves the top-ranked set.Each exit order records which rule triggered it.
AGT-10ShouldRebalance band: skip trades that change a position's weight by less than 1% of equity.Small weight drifts produce no orders.

Position sizing

Riskier stocks get smaller positions, and no single stock or sector can dominate the portfolio.

IDPriorityRequirementAcceptance criteria
AGT-11MustSize positions inversely to volatility.Weights are recorded with each stock's 63-day volatility used to compute them.
AGT-12MustCap any single position at 5% of equity and any sector at 25%.No fill takes a position or sector above its cap.
AGT-13MustCap the number of positions at 20 (configurable).Portfolio never exceeds the cap.
AGT-14ShouldVolatility target: scale total exposure so estimated portfolio volatility is at or below 15% annualized.Pre-trade estimated volatility is logged and does not exceed the target.

Risk controls

This is the loss-limiting layer: exposure shrinks as the market regime worsens, every position has a broker-side stop, and losses trigger automatic brakes.

IDPriorityRequirementAcceptance criteria
AGT-15MustRegime-based exposure: maximum invested share depends on the REG-1 label — Risk-On 100%, Neutral 80%, Cautious 50%, Risk-Off 20%.Total exposure after each run is at or below the cap for that day's label.
AGT-16MustProtective trailing stop on every position at 2.5 × ATR (limited to 3–15%), placed as a broker-side order so it works even if the app is down.Every open position has an active stop at the broker; a stop is not reset unless the position size changes.
AGT-17MustDaily loss limit: if equity falls 2% or more from the prior close, switch to reduce-only (sells allowed, no buys) for the rest of the day.A simulated −2% day blocks all buys and logs the reason.
AGT-18MustDrawdown circuit breaker: if equity is 10% or more below its peak, cap exposure at 20% and require a manual reset to resume normal sizing.Breach triggers the cap and an alert; normal sizing resumes only after a user reset.
AGT-19MustPre-trade checks on every order: no shorting, no leverage (buys ≤ buying power plus same-run sale proceeds), no sale larger than the position held, and the AGT-12 to AGT-15 caps.Orders failing any check are rejected with the specific reason.
AGT-20MustSells execute before buys in each run.Order log shows all sells timestamped before buys in the same run.

AI reviewer

The AI reviewer is optional and one-directional: it can veto buys with a cited reason, never add risk.

IDPriorityRequirementAcceptance criteria
AGT-21ShouldThe reviewer reads the plan plus recent dated headlines for each buy candidate and may remove buys with a stated reason (e.g. pending lawsuit, guidance cut, merger news).Output is limited to removals; any attempt to add or enlarge a trade is ignored and logged.
AGT-22MustThe reviewer cannot block or change sells, stops or risk-limit actions.Prompt tests confirm sells pass through unchanged.
AGT-23MustIf the reviewer fails or times out, the run proceeds with the deterministic plan and logs that review was skipped.A simulated API failure produces a completed run with a "review skipped" entry.
AGT-24MustThe reviewer's reasons cite the headline and its date (NFR-5 grounding).Every removal has a source and date.

Journal and transparency

Every run and order is recorded permanently with its reason, and the user sees the same record the agent acted on.

IDPriorityRequirementAcceptance criteria
AGT-25MustAppend-only journal of every run: time, mode, regime, exposure cap, equity, risk state, and every order (proposed, rejected, submitted, filled) with its plain-language reason.No update or delete path exists; each order links to its run.
AGT-26MustA Trading Agent page shows positions, open stops, today's plan, recent orders with reasons, and current risk state (normal, reduce-only, circuit breaker, killed).Every field matches the journal and the broker.
AGT-27MustPerformance vs SPY: return, volatility, max drawdown, Sharpe, worst month and costs paid, shown separately for Paper and Live.Paper and Live results are never combined.
AGT-28ShouldAlerts (via ALR-2 channels) on fills, stop triggers, risk-state changes and failed runs.Each event sends one alert within 5 minutes.
AGT-29MustIf a scheduled run fails (data, broker or code error), no positions are left without stops, and the user is alerted.Fault-injection tests show stops remain and an alert is sent.

Validation and go-live

Live trading stays off until a 10-year backtest and 3 months of paper trading show the risk rules actually reduce losses.

IDPriorityRequirementAcceptance criteria
AGT-30MustValidation gate before Live: (a) a hypothetical backtest of at least 10 years including 2008, 2020 and 2022, after costs, showing lower max drawdown than SPY and than the same agent without regime and stop rules; and (b) at least 3 months of Paper trading with drawdown inside the configured limits.Report shows both comparisons; Live stays disabled until it passes.
AGT-31MustBacktests use point-in-time data and constituents (NFR-1), or are labeled with a survivorship-bias caveat.Report names its data sources and states any bias.
AGT-32MustBacktests charge 10 bps per trade side and model stop exits at the next available price.Assumptions appear on every backtest chart, with the TRK-4 "Hypothetical" label.
AGT-33ShouldAll limits (caps, stops, loss limits, regime exposure) live in one config file; every change is versioned and logged.Journal entries show the config version used for each run.

Compliance

The agent trades only the owner's account until a securities lawyer confirms what offering it to other users requires. This is not legal advice.

IDPriorityRequirementAcceptance criteria
AGT-34MustUntil legal review is complete, the agent trades only the account owner's own account.No multi-user trading path is enabled.
AGT-35MustBefore any other user can enable automated trading, confirm with a securities lawyer whether investment adviser registration (SEC or state) and broker approval (e.g. Alpaca's OAuth/partner terms) are required.Written sign-off is recorded before the feature flag opens to other users.
AGT-36MustShow "Automated trading can lose money; past performance doesn't predict future results" on the agent page and at opt-in.Disclosure visible on both screens.

Open questions

  • Use the short-term score, the long-term score, or a blend for candidates?
  • How much capital goes into the first Live phase, and what stays outside the agent?
  • Trailing stops (protect gains) or fixed stops from entry (simpler to explain)?
  • Is the circuit-breaker reset owner-only, or does it auto-reset after N days?
  • Should uninvested cash move to a short-term Treasury ETF in Risk-Off?

Beat TradingView: Gap and Differentiation Requirements

Oct 1, 2026 · Amit

Strategy

We beat TradingView by being the platform that makes accountable calls, not by out-building its toolbox. TradingView shows you the chart and leaves the judgment to you; StAnalysisEngine tells you what the evidence says, why, and how often it has been right.

AreaPlanWhy
Charting, coverage, scripting, community sizeReach "good enough" parity so users don't have to leaveTradingView leads by years here; matching it fully isn't realistic or necessary
Signals, explanations, scored track record, portfolio analysis, regimeWin outright and make them visible everywhereTradingView has nothing comparable; this is the reason to switch
Data licensing, confidence, validationFix firstThese undercut the trust pitch and block a public launch

Requirement IDs continue the existing spec's style. Priority: Must for that phase's release, Should soon after, Could later.

Foundation fixes (Phase 0)

Nothing else ships publicly until the data is licensed and the track record measures the signals users actually see.

IDPriorityRequirementAcceptance criteria
FND-1MustReplace yfinance with a licensed data vendor whose terms allow display to users: prices (intraday at least 15-min delayed), fundamentals, estimates, earnings, ETF holdings.Signed license on file; no yfinance call remains in production code paths.
FND-2MustStore point-in-time snapshots of fundamentals and estimates daily from the vendor, so scores and backtests never use later data (NFR-1).The S3 look-ahead test exists, runs in CI and blocks release on failure.
FND-3MustThe public track record scores the stock-page Buy/Hold/Trim signals (SCR-1/SCR-2), not a separate momentum ranking.Every signal shown on a stock page on a given date appears in the track record for that date.
FND-4MustConfidence is a calibrated probability of a hit at the stated horizon, fitted on out-of-sample history.Calibration chart shows stated vs actual within ±5 points per bucket, with ≥30 predictions per bucket.
FND-5MustThe regime model passes a forward-risk validation gate (REG-10) before it is shown without a failure caveat.Validation report attached to the release.
FND-6MustPublish a methodology page for scores, confidence, regime and track record.Every signal and chart links to it.

Differentiators: what TradingView can't do

These put the model's judgment and its proof directly on the chart, where TradingView users spend their time.

IDPriorityRequirementAcceptance criteria
DIF-1MustSignal overlay: every past Buy/Hold/Trim signal plotted on the chart, colored by outcome (hit, miss, pending).Clicking a marker shows the signal, confidence, reasons at the time, and what happened.
DIF-2MustPer-stock track record panel: this ticker's hit rate, average excess return vs SPY and worst miss, beside the chart.Numbers match DET-3 history; groups under 30 show "not enough data yet".
DIF-3MustEvidence panel: the score, top 3 drivers and top 2 drags, sector rank and regime, in one card next to the chart.Card loads with the chart and shows its as-of date.
DIF-4MustScore history line: short- and long-term scores plotted as a sub-chart under price.Score line aligns to price dates; a 15-point weekly move is marked.
DIF-5MustVerifiable record: publish a daily cryptographic hash of all new predictions to a public, timestamped location.Anyone can verify a past prediction existed on its stated date.
DIF-6MustPortfolio impact preview: before any trade, show how it changes concentration, sector weights, beta and portfolio score.Preview appears on the order ticket and the stock page for held portfolios.
DIF-7ShouldSimilar setups: "the last N times this stock had this score and regime, what happened over the horizon".Shows N, median and range of outcomes; under 30 cases shows the caveat.
DIF-8ShouldAI analyst with citations (ASK-1/ASK-2 completed): answers about a stock or portfolio cite app data and dated sources, and say "no clear cause found" when needed.Every factual claim carries a source or app-data reference.
DIF-9ShouldRegime overlay: shade the price chart by regime label over time.Shading matches market_regime_daily for each date.

No-code strategy builder

TradingView makes users write Pine Script and its backtests are easy to overfit; ours should be point-and-click and honest by default.

IDPriorityRequirementAcceptance criteria
STB-1MustBuild entry and exit rules from dropdowns: app scores and signals, factors, indicators (CHT-3), regime label, price vs moving averages, earnings windows.A rule set saves and reruns without code.
STB-2MustBacktests use point-in-time data and historical index membership, charge costs (default 10 bps per side) and model slippage.Assumptions are listed under every result.
STB-3MustEvery backtest reports out-of-sample results: rules are fitted on one period and tested on a later one (walk-forward).In-sample and out-of-sample results are shown side by side.
STB-4MustOverfitting warning: show how many rule variants the user has tried and flag results likely due to chance.Warning appears after 20+ variants on the same universe.
STB-5MustResults vs SPY and vs the app's own model portfolio: CAGR, volatility, max drawdown, Sharpe, worst month, turnover.All metrics appear for all three.
STB-6ShouldRun a saved strategy forward in paper mode and start its own live track record.Forward results are kept separate from the backtest, labeled "Live paper".
STB-7ShouldPython strategy SDK for power users, running the same engine as the no-code builder.The same rules in no-code and Python give identical results.
STB-8CouldImport a subset of Pine Script (indicators and simple entry/exit conditions).Common indicator scripts convert and match TradingView values within 0.5%.

Scored community ideas

TradingView ideas are never graded; ours are scored automatically, so reputation is earned by results, not followers.

IDPriorityRequirementAcceptance criteria
COM-1MustUsers publish an idea with ticker, direction, horizon and optional target and stop; it is timestamped and locked.A published idea can't be edited or deleted, only closed early (which is recorded).
COM-2MustEvery idea is scored automatically at its horizon: return, excess return vs SPY, hit or miss.Score appears on the idea within one trading day of maturity.
COM-3MustAuthor profiles show their full record: hit rate, average excess return, worst idea, number of ideas.Profiles with fewer than 30 scored ideas show "not enough data yet".
COM-4ShouldLeaderboards rank by risk-adjusted excess return with a minimum sample, never by raw return alone (as PPR-2).Leaderboard shows return, volatility and sample size for each author.
COM-5ShouldFollow authors and get alerts on their new ideas.Follower receives one alert per new idea.
COM-6MustModeration: report button, rules against pump-and-dump and paid promotion, and a disclosure field for authors' positions.Reported ideas are reviewed within 24 h; position disclosure shows on the idea.
COM-7ShouldThe app's model appears on the leaderboard as its own author, scored by the same rules.Model and human records use identical scoring code.

Community safety and compliance

A trading community attracts pump-and-dump schemes and bad advice, so safety rules ship with the first public post. Legal points need a securities lawyer's review; this is not legal advice.

IDPriorityRequirementAcceptance criteria
SAF-1MustCommunity guidelines banning pump-and-dump, coordinated trading, undisclosed paid promotion, impersonation and harassment.Users accept them at sign-up; violations lead to warnings, then bans.
SAF-2MustReport button on every post, comment, group and profile; reports reviewed within 24 hours.Review time is tracked and reported monthly.
SAF-3MustAutomated flags for sudden spikes in mentions of small or illiquid stocks, and for repeated identical posts across accounts.Flagged posts are held for review before wider distribution.
SAF-4MustPosition disclosure: posts about a ticker show whether the author holds it (self-declared, or verified via linked broker).Disclosure appears on every ticker post.
SAF-5Must"Not investment advice" notice on all community content; paid promotions labeled.Notice visible on posts, strategies and profiles.
SAF-6MustPrivacy: portfolio sharing is opt-in and shows percentages, not dollar amounts, by default.No dollar values appear publicly unless the user enables them.
SAF-7MustBlock and mute for users, tickers and keywords.Blocked users can't see or contact the blocker.
SAF-8MustAccounts are for adults (18+), with age confirmed at sign-up and verified before broker connection.Underage sign-ups are refused.
SAF-9MustLegal review before launch of: paid strategy subscriptions, copy trading, paid mentoring, and any public performance advertising.Written sign-off recorded per feature.

Roadmap

Phase 1 is where we pull ahead: the differentiators only matter once Gate A proves the data and record are trustworthy. Gate B requires at least 6 months of live results; Gate C must pass before trading or ideas open to the public, and the SAF safety rules ship with the first public post.
