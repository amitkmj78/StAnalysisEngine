How a prediction actually gets made

Five steps, every one of them checkable.

The forecast on every ticker page is built the same way, in the same order, with nothing hidden between steps.

01

Price-native features only

RSI, MACD, Bollinger position, and lagged returns — computed from the ticker's own trading history. The core numeric forecast never touches news, filings, or sentiment, so it can be backtested honestly against real historical dates.

gradient-boosted regressor
02

Walk-forward training, never a peek ahead

For every day in the backtest window, the model is trained only on data that existed strictly before that day, then asked to predict it. The day's own outcome is never in its own training set — the single most common way naive backtests lie to you.

no look-ahead leakage
03

Return shrinkage, applied because it measurably helps

A raw model's predicted move is dampened toward "no change" before it's ever shown — not for show, but because testing it across tickers and time windows produced a better real-world error rate than trusting the raw number. If a future test stops showing that benefit, the shrink factor changes.

validated by backtest, not assumed
04

Scored against doing nothing

Every forecast ships next to a naive baseline: "assume tomorrow's price equals today's close." RMSE, MAE, and MAPE are reported for both, side by side, so beating a coin flip isn't quietly implied — it's measured.

RMSE · MAE · MAPE vs. naive
05

Saved predictions verify themselves

Save a forecast — 5 to 60 days out, your choice — and a background job checks it automatically once the target date arrives — a live accuracy record that builds over time, distinct from the historical backtest above it. Nobody has to remember to come back and check. An admin control can pause this job without touching any code.

auto-verified, every 15 minutes · adjustable horizon
